NoSQL : Not Only SQL
--------------------

WHAT IS NoSQL ?
---------------

NoSQL is a non relational DBMS that does not require a fixed schema, avoids joins and is easy to scale. NoSQL database is used 
for distributed data stores with humongous data storage needs. NoSQL is used for big data and real time web apps for example:
Companies like Twitter(X) , Meta, google that collect terabytes of user data every single day.

NoSQL data base stands for not only SQL or Not SQL introduced by Carlos Strozzi in 1998. Traditional RDBMS uses SQL syntax to store and retrieve data for further insights. Instead a NoSQL database system encompasses a wide range of database technology
that can store structured, semi structured, unstructured and polymorphic data.

FEATURES :
---------

1) NON RELATIONAL : 

NoSQL databases never follow the relational model.
Never provide tables with flat fixed column records.  
Work with self contained aggregates or BLOBS(binary large object). 
Does not require object relational mapping and data normalization.
No complex features like query languages, query planners, referential integrity joins, ACID.

2) Schema Free :
---------------
NoSQL databases are either schema free or have relaxed schema.
Do not require any sort of definition of the schema of the data.
Offers heterogenous structures of data in the same domain.

3) Simple API :
---------------
Offers easy to use interfaces for storage and query data provided.
API's allow low level data manipulation and selection methods.
Text based protocol mostly used in HTTP REST with JSON.
mostly used no standard based NoSQL query language.
web enabled databases running as internet facing services.

4) Distributed :
---------------
Multiple NoSQL databases can be executed in a distributed fashion.
Offers autoscaling and fail over capabilities.
Often ACID concept can be sacrificed for scalability and throughput. 
Mostly no synchronous replication between distributed nodes asynchronous multi master replication, peer to peer.

When Uses SQL :
---------------
SQL is the easiest language used to communicate with the RDBMS.
For analyzing behavioural related and customised sessions.
Building custom dashboards.
It allows us to store and get data from the database quickly.
Preferred when we want to use joins and executed complex queries.

When uses NoSQL :
---------------
When ACID support is not needed.
When traditional RDBMS model is not enough.
Data which need a flexible Schema.
Constraints and validation logic not required to be implemented in databases.
Login data from distributed sources.
It should be used to store temporary data like Shopping Karts, Wish lists and etc.

Types of NoSQL Databases :
-------------------------

NoSQL databases are mainly categorised into 4 types :
   1) Key Value Pair
   2) Column Oriented
   3) Graph Based
   4) Document Oriented
Every category has it's unique attributes and limitations. None of the above specified database is better to solve all the problems. Users should select the database based on their product needs.

Key Value Pair : Data is stored in Key Value pairs. It is designed in such a way to handle lots of data and heavy load. Key value pair storage databases store data as a hash table where each key is unique and the value can be a JSON, BLOB, STRING and etc. For example a key value pair may contain a key like language associated with the value like python.
EXAMPLE :[{"eid":101,"name":"ratan tata","salary":45000},
         {"eid":102,"name":"mukesh ambani","salary":40000},
         {"eid":103,"name":"anil ambani","salary":35000}]

 It is one of the most basic NoSQL database example. This kind of NoSQL database is used as a collection,
dictionaries, associative arrays and etc. Key value stores help the developer to store schema less data. they work best for shopping kart contents. Redis, Dynamo, Riak are some NoSQL examples of Key value pair Database.

2. Column Oriented : It work on Columns and are based on big table paper by Google. Every Column is treated separately.
example : {" eid " : [101,102,103], "name" : ["ratan tata", "mukesh ambani", "anil ambani"],"salary":[45000,40000,35000]}

HBase, Cassandra, HyperTable are NoSQL query Examples of Column based database.


3. Graph Based : A graph type database stores entities as well the relations amongst those entities. the entity is stored as a node with the relationship as edges. an edge gives a relationship between nodes. every node and edge have a unique identifier. Neo4J, InfiniteGraph, OrientDB, FlockDB are some popular graph based databases.

4. Document Oriented : It Stores and retrieves data as key value pair but the value part is stored as a document. The document is stored in JSON format. the value is understood by the DB and can be Queried. MongoDB, CouchDB, Amazon SimpleDB, LotusNotes are Popular example of Document oriented DBMS systems.

CAP THEOREM :
-------------
It is very important the limitations of NoSQL Databases. NoSQL cannot provide cannot provide consistency and high availability. This was first expressed by Eric brewer in CAP theorem 
Cap theorem states that we can only achieve at most two out of three gaurettes for  a database:
i)Consistency ii) availability ii) partition tolerance  here :

1)	Consistency means that all nodes in the network data see the same data at the same time. 
2)	Availability : availability is a Guarente every request receives a response about whether it was successful or fail. However it does not guarantee that the read request returns the most recent right. The grater no of users a system can cater to better is the availability . 
3)	 Partition tolerance: it is a guarantee that the system continues to operate despite Arbitrary message loss or failure of part of the system. In other words , even if there is a network outage in the data center and some the computers are unreachable, still the system continues to perform . 

Out of these tree guarantees no system can provide more than two guarantee. Since in the case of the distributed systems, the portioning of the network is a must, the trade off is always between consistency and availability.

CREATING A NEW DATABASE OR OPENING AN EXISTING ONE :
--------------------------------------------------
IN MONGODB THE DEFAULT DATABASE IS TEST. IF WE DIDNOT CREATE ANY DATABASE OR USE AND EXISTING ONE, THEN COLLECTIONS WILL BE STORED IN THE TEST  DATABASE. MONGODB USES THE "use" COMMAND TO CREATE A DATABASE OR OPEN AN EXISTING ONE. THE COMMAND WILL CREATE A NEW DATABASE IF IT DOESNOT EXIST, OTHERWISE IT WILL RETURN THE EXISTING ONE. THE BASIC SYNTAX OF THE USE COMMAND IS 
SYNTAX : use database_name 
EXAMPLE : if we want to use a database with name "Company" then "use" command be as follows :
use Company.

CHECKING THE DATABASE CURRENTLY IN USE :
---------------------------------------
TO CHECK THE DATABASE CURRENTLY IN USE THE "db" COMMAND IS USED. TO BE NOTED, A NEWLY CREATED DATABASE IS NOT LISTED USING THE COMMAND "show dbs" UNTIL WE ARE CREATING A COLLECTION INTO IT. BUT ON CHECKING THE DATABASE CURRENTLY IN USE USING "db" COMMAND THE NEWLY CREATED DATABASE IS SHOWN.
